# 1. Two Sum

- **難易度**: Easy
- **トピック**: 配列, ハッシュマップ
- **URL**: https://leetcode.com/problems/two-sum/

## 問題概要

整数の配列 `nums` と整数 `target` が与えられる。
合計が `target` になる2つの数の**インデックス**を返せ。

- 各入力には **exactly one solution** が存在する
- 同じ要素を2回使ってはいけない
- 答えの順序は問わない

### 例

```
Input:  nums = [2,7,11,15], target = 9
Output: [0,1]  (nums[0] + nums[1] = 2 + 7 = 9)

Input:  nums = [3,2,4], target = 6
Output: [1,2]

Input:  nums = [3,3], target = 6
Output: [0,1]
```

### 制約

- 2 <= nums.length <= 10^4
- -10^9 <= nums[i] <= 10^9
- -10^9 <= target <= 10^9
- 解は必ず1つだけ存在する

### Follow-up

O(n^2) より速いアルゴリズムを考えられるか？

## 考察

- ブルートフォース: 2重ループで全ペアを試す → O(n^2)
- 最適化: 辞書に「見た数 → インデックス」を保存しながら1回のループで探索 → O(n)
- ループ中に辞書追加前に確認することで、自分自身とのペア問題を回避

## 解法

### Python

- **計算量**: 時間 O(n), 空間 O(n)
- 辞書の検索・追加が O(1) なので、ループ1回の O(n) で完了

## 学んだこと・反省

### 計算量 (Big O) の基礎

- O(n^2): 2重ループ。nが増えると n×n で爆発的に遅くなる
- O(n): 1回のループ。辞書を使えば検索が O(1) なのでこれが可能
- O(n log n): ソート
- O(1): 辞書の検索・追加、配列のインデックスアクセス
- 面接では「時間計算量は O(n)、空間計算量は O(n) です」とセットで答える

### Python の辞書操作

- `d = {}` で空の辞書を作成
- `d[key] = value` で追加
- `if key in d` で存在チェック（O(1)）
- `d[key]` で値の取得

### 解法の流れ

1. **ブルートフォース (O(n^2))**: 2重ループで全ペアを試す → 動くが遅い
2. **2パス辞書 (O(n))**: 先に全要素を辞書に入れてからもう1回ループで探す → 自分自身とのペアを `d[complement] != i` で回避する必要あり
3. **1パス辞書 (O(n))**: 辞書に追加する前に確認する → 自分自身問題が自然に解消される、最も無駄のない書き方

### ポイント

- まず動くコード（ブルートフォース）を書く → 最適化は後
- 辞書は「値 → インデックス」を一瞬で引ける電話帳のようなもの
- `target - nums[i]` でペアの相手を求め、辞書で探すのがこの問題のコア
